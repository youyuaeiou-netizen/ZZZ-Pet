# Q 宠动画制作工作流

本文记录当前 二维角色的可复现制作过程。仓库里同时放有最终角色帧、用户确认的参考图、11 段源视频、逐动作提示词和确定性的帧处理工具。按相同的提示词重新调用生成式视频服务只能得到相似结果；要重现完全相同的动画，应直接使用仓库所附源视频或现成角色帧。

## 1. 先锁定造型基准

唯一标准站姿是 [`ellen-flat2d-reference-original.png`](reference-images/ellen-flat2d-reference-original.png)。睡眠动作另使用已确认的戴眼罩站姿和坐姿图。角色固定为平面手绘 Q 版：黑红头发、红眼、银色发夹、灰色鲨鱼服、白色牙齿领口、浅色椭圆腹部、短臂和短脚。

造型参考图和姿势参考图一同用于相邻动作，确保同一人物的头身比例、服饰细节和颜色保持一致。仓库以这些已批准图像及 动画帧包作为可直接对照的标准。

## 2. 编写每个动作的提示词

使用 `workflow/prompts/` 中逐动作拆分的提示词。新动作也按同一规则撰写：

1. 先写角色身份、发型、服饰、颜色、描线和二维画风，再指定本动作唯一参考图。
2. 用秒数划分动作阶段，写清起始姿态、主要动作、恢复姿态和循环点。
3. 指明 16:9 固定镜头、完整全身、人物大小与位置、纯绿幕 `#00FF00`、无地面投影。
4. 写明不希望出现的变化：不换装、不变形、不增删肢体、不移动镜头、不增加文字或未指定道具；除动作需要外不改变轮廓。
5. 对入睡、醒来和拖放使用明确的姿势参考。坐下属于实际动作，不要逐帧移动裁切框来“吸附”脚底。

将动作拆成独立提示词和独立视频文件，一段视频只做一个动作。用提示词预览确认动作符合预期后再下载，不要仅凭文件名推定内容。完整可直接复制的动作提示词在 `workflow/prompts/`；11 个当前动作的生成结果在 `workflow/source-videos/`。另有 5 个尚未加入 动画包的扩展提示词，见文件名 `blink.md`、`nod.md`、`shake_head.md`、`shy.md`、`look_around.md`。

`workflow/source-materials.sha256` 记录提示词、参考图与视频文件哈希。修改这些文件后，用 `python tools/create_source_manifest.py` 重建清单；检查现有清单时加 `--check`。

## 3. 生成视频并准备输入

当前动作使用 16:9、纯绿背景、固定镜头，推荐 1280×720 或 1920×1080。提示词按 5 秒设计，但最终截取区间按实际动作和已确认帧包确定。源视频以动作 ID 命名；`put-up.mp4` 在仓库中重命名为 `drag_hold.mp4`，其内容未改动。

| 动作 | 源视频 | 帧包时长 |
| --- | --- | ---: |
| 待机 | `idle.mp4` | 2.000 秒 |
| 挥手 | `wave.mp4` | 3.500 秒 |
| 入睡 | `sleep_enter.mp4` | 5.000 秒 |
| 坐睡 | `sleep_idle.mp4` | 2.667 秒 |
| 醒来 | `wake.mp4` | 5.000 秒 |
| 开心 | `happy.mp4` | 2.833 秒 |
| 抚摸 | `pet.mp4` | 5.000 秒 |
| 喂食 | `eat.mp4` | 6.000 秒 |
| 伸懒腰 | `stretch.mp4` | 5.000 秒 |
| 拖起悬空 | `drag_hold.mp4` | 5.000 秒，循环 |
| 放下 | `put_down.mp4` | 3.000 秒 |

真实生成结果和最终裁切区间以 `workflow/video-jobs.json` 为准。绿幕抠像模式为 `green`；不修改原视频，也不去除生成服务附带的标识。

## 4. 从视频生成透明动画帧

工具 `tools/build_flat2d_pack.py` 使用 FFmpeg 解码、NumPy/Pillow 处理绿幕、估算待机帧的角色高度和脚底锚点，再把统一变换应用到各动作。输出为 **616×656 RGBA PNG、12 FPS**；运行时逻辑画布为 **308×328**，锚点为 **(154, 315)**。帧底部保留额外透明留白，以便各动作共用角色尺度并容纳喂食道具。同内容的连续帧合并时长，空帧、假透明、越界和缺失输入会报错。

安装 Python 依赖并运行：

```powershell
python -m pip install -r workflow/requirements-animation.txt
pwsh -NoProfile -File workflow/rebuild-flat2d.ps1
```

生成结果位于 `build/generated/ellen-flat2d/`，不覆盖既有目录。检查 `report.json` 后，可用桌宠预览参数查看输出：

```powershell
dotnet run --project src/DesktopPet/DesktopPet.csproj -- --preview-pack build/generated
```

## 5. 接入程序与发布

动画由角色包的 `character.json` 描述：每个动作包含帧路径、逐帧时长、循环标记、触发条件和下一动作。当前版本已将 11 个动作的最终 PNG 帧包含在 `characters/ellen-flat2d/` 中。拖起与放下动作的 96 帧做了固定 RGB 曲线匹配；只影响 RGB，不改变 Alpha 和轮廓，其余帧保持原样。

构建桌面程序：

```powershell
dotnet run --project tests/DesktopPet.Smoke/DesktopPet.Smoke.csproj -c Release
dotnet run --project tests/DesktopPet.Monitoring.Tests/DesktopPet.Monitoring.Tests.csproj -c Release -- build/.cache/monitoring-tests
dotnet run --project tests/DesktopPet.Search.Tests/DesktopPet.Search.Tests.csproj -c Release -- build/.cache/search-tests
dotnet publish src/DesktopPet/DesktopPet.csproj -c Release -r win-x64 --self-contained true --output build/publish
```

对外分发请使用便携打包脚本，而不是直接压缩开发 publish 目录：

```powershell
pwsh -NoLogo -NoProfile -File tools/publish_portable.ps1
pwsh -NoLogo -NoProfile -File tools/test_portable.ps1 -ReleaseFolder build/releases/DesktopPet-0.3.1-beta.3-win-x64 -EvidenceRoot build/release-check-beta3
```

便携 ZIP 只打包 `ellen-flat2d` 的 540 个引用帧。验包脚本核对全部帧哈希，并用隔离用户数据启动实际 EXE，检查全新设置和无效角色选择均显示 2D，再正常退出。下载后完整解压到新目录运行 `DesktopPet.exe` 或 `Start-2D-Pet.cmd`；如需分发，连同 `.sha256` 文件一起提供。

## 6. 验收清单

- 所有图片为统一大小的 RGBA，Alpha 有效，角色不被画布裁切。
- 深色和浅色背景都检查轮廓，确认没有绿边、浅色光边和残留投影。
- 连续播放待机、拖起、放下、待机，检查循环接缝、脚底位置和颜色连续性。
- 逐动作查看眼罩、喂食道具、手脚轮廓和回到待机时的造型。
- 改变显示缩放，并在目标显示器 DPI 下实际运行检查。
- 构建报告中的机械检查不代替视觉确认；当前桌面 DPI 的最终观感仍待使用者验收。
