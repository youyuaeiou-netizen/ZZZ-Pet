# Pet 本地模型控制

宠物右键或托盘打开“轻工具 → 系统监控”，进入“进阶功能 → 插件”，在“已安装”列表点击“本地模型控制”。网关独立运行，关闭 Pet 不会终止推理服务。

本地模型控制是可选扩展，Pet 提供原生页面，独立插件包提供网关及自带运行时。插件管理支持下载/导入安装、升级、卸载、打开、关闭。关闭和卸载停用 Pet 管理入口，保留模型文件、上下文设置及独立服务，DSH/OpenCode 继续使用；解除接入是另外的操作。旧版用户保留已安装状态，升级后可安装真实插件包。

插件首页统一列出已安装的本地模型与数据插件：点击名称打开功能或配置，右侧滑动开关启停，“⋯”菜单提供详情和卸载。所有可安装的扩展与 JSON 模板导入均在“安装插件”窗口中，不在列表页展开具体插件的功能控件。滑动开关采用 150ms 动画。

- 启动 Ollama 服务：启动本机安装的 Ollama，不停止其他程序。
- 加载模型：预加载选定模型，以当前上下文容量驻留。
- 卸载模型：等待本网关正在处理的请求结束，释放该标签的模型驻留，保留 Ollama 服务；客户端下次请求可重新加载。
- 上下文：只提供 48K、64K、96K、128K 四个固定档位。首次按独立显存预选；显存未知时默认 64K。Qwen3.5 9B 无论标签元数据报告多大，都限制为最高 128K。容量低于 48K 的模型按其可用容量运行并禁用档位选择；元数据不可用时禁用调整。模型族按 Ollama 权重摘要及 `-数字K` 上下文后缀识别，沿用旧设置并将不再支持的值归一到有效档位，不创建或删除 Ollama 标签。

网关只监听 `127.0.0.1:11435`，提供 `/v1/models` 和 `/v1/chat/completions`。DSH/OpenCode 的 Ollama 提供方必须使用 `http://127.0.0.1:11435/v1`。离线时请求失败，不自动直连 Ollama。支持文本、内嵌 base64 图片、流式回复、工具调用和工具结果、请求中止；不支持远程图片 URL 或强制 `tool_choice`。

推理控制优先依据 Ollama `thinking.values` 元数据：布尔开关与命名强度分别处理，不支持的选项明确报错。旧版 Ollama 缺少该元数据时按已有 thinking 能力兼容布尔开关；旧 GPT-OSS 按其命名等级处理。不支持 thinking 的模型不发送 `think`。

未指定推理选项时不发送 `think`，遵循模型默认行为。DSH 0.2.0-rc.2 的界面把布尔开启显示为 High；`tools/patch_dsh_reasoning_labels.mjs` 可生成本地兼容包，仅将 pet-local 中仅支持 off/high 的 Qwen3.5 模型显示为“默认／关闭／开启”。替换前保留原 app.asar；DSH 升级后该界面修正可能被覆盖，脚本会拒绝结构不匹配的版本。

控制接口：GET `/control/status`；POST `/control/service/start`、`/control/settings`（model/context）、`/control/load`、`/control/unload`（model）。上下文状态存放于 `%LOCALAPPDATA%\DesktopPet\model-gateway.json`。浏览器来源请求被拒绝，控制页面使用原生 HTTP 客户端。本网关串行化推理及加载/卸载；其他直接访问 11434 的客户端不受此队列控制。

发布脚本 `tools/publish_portable.ps1` 包含独立自带运行时的 `model-gateway` 子目录。部署后运行 `tools/install_model_gateway.ps1 -PetDirectory C:\pet\DesktopPet`，注册普通用户权限的登录任务。Pet 也会尝试启动已启用插件的网关。已有 Ollama 登录任务改用 `DesktopPet.ModelGateway.exe --ollama-service`，通过无控制台的启动器运行 Ollama，并将输出保存到 `%LOCALAPPDATA%\DesktopPet\logs\ollama.stdout.log` 和 `ollama.stderr.log`。插件注册状态存放于 `%LOCALAPPDATA%\DesktopPet\local-model-plugin.json`。

客户端配置中的 `contextWindow` / `limit.context` 是客户端对话压缩预算，不是 Ollama 运行容量。授权接入后，插件按模型族只向 DSH/OpenCode 提供一个稳定模型入口，并同步其上下文预算与网关 `num_ctx`；已有的上下文标签仍可用于兼容旧会话。较大容量受实际内存与显存限制，元数据上限不代表当前硬件能高效运行。

## 安装、初始化及客户端接入（0.3.1-beta.5）

1. “安装插件”从官方 GitHub Release 下载目录与 ZIP，或导入本地 ZIP。下载校验整包 SHA256，导入/下载均校验清单、文件摘要、最低 Pet 版本及 Windows 解压路径。取消或校验失败不更改当前版本。
2. 打开插件详情，进入“环境设置／首次初始化”。选择检测到的 Ollama 地址及程序，也可输入本机地址或选择 `ollama.exe`。未安装时可打开安装说明。仅连接本机 HTTP，不扫描模型文件。
3. 新安装默认勾选登录后台启动，确认初始化后注册当前用户的普通权限任务；使用无控制台进程，关闭 Pet 后可继续服务客户端。已有启动选择保留。没有 PowerShell 7 的电脑使用 Windows 自带 PowerShell 执行兼容的 ScheduledTasks 模块；无需其他 AI 或额外 .NET 安装。
4. “接入 DSH / OpenCode”选择全局、项目或 DSH profile 配置，先预览再确认。新增 `pet-local` 提供方，保留原提供方、默认模型及其他配置；仅勾选“设为默认”才更改默认。DSH 使用不含秘密的占位 Authorization，不要求用户手工设置密钥。
5. 授权自动同步后，独立网关每 10 秒同步模型、能力及预算，Pet 退出或关闭插件后也能继续。模型元数据缓存 30 秒。人工修改插件部分时暂停，重新预览确认可重新接管。默认模型删除时暂停并提示选择替代，不自动切换。
6. 解除接入先备份，恢复插件接管前的默认值并移除其提供方；其他修改保留。插件部分被人工修改时拒绝恢复。复杂、内联或重复 YAML 结构明确拒绝，不执行 `!!js`。

配置文件在 `%LOCALAPPDATA%\DesktopPet`：`model-runtime.json`（环境/登录选择）、`model-gateway.json`（模型上下文）、`model-clients.json`（授权和管理记录）、`local-model-plugin.json`（插件注册）。版本化网关位于 `plugins\pet-local-model`。客户端备份与原配置同目录，文件名带 `.pet-backup-`。

新增接口：GET/POST `/control/environment`；GET `/control/clients`；POST `/control/clients/preview`、`apply`、`detach`；POST `/control/restart`（有推理请求时拒绝）。控制端点保持仅本机，拒绝浏览器 Origin / Sec-Fetch-Site 请求。

分发脚本：`tools/package_local_model_plugin.ps1` 生成 ZIP、SHA256 及 `pet-local-model-catalog.json`，三者上传同一官方 GitHub Release 后市场才可下载。脚本不会上传；目前尚未发布。`tools/publish_portable.ps1` 生成兼容的完整 Pet 包。

旧网关没有安全重启 API 时，安装包保留，既有插件启动任务更新为新路径，并提示重启电脑后生效；不强制终止现有推理服务。外部服务占用端口时需要处理占用。
